# Data run runbook

This is what each scheduled run does. Each match follows the schema of the existing files in `public/data/` (use the newest one as the template).

0. **Grade yesterday (morning run only).** For each match in the previous day's file, add `result: {home, away}` and append every graded pick the site showed to `public/data/results.json` → `legs`: `{date, match, group, pick, p, odds, won}`. Include the best bet, every slip row whose verdict was Bet or Lean, the builder and any priced prop, using the chance the page showed. `group` must be one of Result, Handicap, Goals, BTTS, Scorer, Corners, Most corners, Cards, Bet builder or Player prop. Skip legs you can't settle from a reliable source. Never add games the user asked to keep off the site.
   - "The chance the page showed" means the engine run with the track-record calibration loaded (`setCalibration(trackStats(legs))` from `results.json`, as `index.html` and `scripts/check.mjs` do). Grade from `results.json` as it stood before today's legs were added.
   - If yesterday already has `result` fields and legs in `results.json` (an evening session graded it), don't add them again.
1. **Pick the matches.** Find today's fixtures (Europe/Warsaw date) and keep 8–12 matches (more is fine when there are big rounds; the user asked for more than 4). Start with every top-tier European game of the day, then the rest of the same round (all Nations League A–D games on a Nations League night), then the best of the rest: Champions League, Premier League, La Liga, Serie A, Bundesliga, Ligue 1, Europa League, Nations League A, major internationals, then Ekstraklasa and other top leagues, plus big clubs and national teams. Skip youth and women's games unless nothing else is on.
   - File each match by its kick-off in Warsaw time. A 23:00 UK kick-off is 00:00 in Warsaw and belongs to the next day's file (13 Nov: Argentina v Uruguay).
2. **Gather the data for each match:**
   - **Odds:** bet365 odds from kickoff.co.uk (`/…-predictions-stats-odds/<home>-vs-<away>/`): 1X2, O/U 0.5–5.5, BTTS, double chance, DNB, win to nil, first goal. Cross-check 1X2, O/U 2.5 and BTTS against a second site (footballpredictions.ai, oddschecker, sportinglife). Never copy one match's ladder into another.
     - KickOff shows bet365 prices as fractions. Decimal = fraction + 1, rounded to 2 dp (11/20 → 1.55, 10/3 → 4.33, 1/40 → 1.03, 15/8 → 2.88).
     - If KickOff can't be fetched, try it again from the main run before falling back (on 13 Nov two research passes were blocked, a third fetch worked). When the ladder comes from elsewhere, `odds.book` must name the bookmaker and the site, and say which lines are missing.
   - **Stats:** statz.ai h2h page for the referee and their per-game fouls, yellows and reds; predicted or confirmed XIs; season per-game corners, fouls, shots and shots on target; top scorers and shooters; bet365 player props. If statz.ai has no page for the match, take the referee's numbers from UEFA match reports and say so in `referee.note`.
   - **Form:** kickoff.co.uk 20-game form, giving goals for/against and xG for/against.
   - **Team news:** injuries, suspensions, returns and new coaches from SoccerNews, Sports Mole, WhoScored, Oddschecker and the clubs' or federations' own posts.
   - **Smaller nations:** when no predicted XI is published, set `lineups.status` to `"pending"` with empty `xi` arrays and list the key players (top scorers, regular starters) with `start` 0.75. The kick-off-minus-40 run fills in the confirmed XIs.
   - **Lineups:** confirmed lineups about 60 minutes before kick-off from WhoScored "confirmed lineups", statz.ai, or federation and club accounts. Confirm with two sources.
   - **Doing it in parallel:** one research agent per match works well. Give each the schema, these rules and an output file, then check every file yourself before merging (odds margins, 11-man XIs, prop players present in `players`).
3. **Player props:** when bet365 props are listed, also give the player per-90 rates when you can find them (`shots90`, `sot90`, `fouls90`, `tackles90` from FBref, WhoScored or Sofascore). Without them the model falls back to position averages, which is deliberately cautious.
   - `fouls90` must be fouls committed. Some sources show fouls won under the same heading; an attacking player above about 1.5 per 90 needs a second source (13 Nov: Wirtz at 2.15 was dropped).
   - `hit` ("4/5") only when the source shows the last five games. A bare percentage with no game count is left out.
   - `teamTotals` must cover the same games as the players' `shots` and `goals`. If the spans differ, leave `teamTotals` (or that side) out.
4. **Build the players list:**
   - Starters get `start` 1 once confirmed and bench players 0.
   - Before that, players in the predicted XI get 0.75–0.9, rotation risks 0.3–0.5, and injured or suspended players are left out.
   - Set `adjust.home` or `adjust.away` to 0.92 when a confirmed XI is missing 2+ of the usual top-3 attackers, and to 0.96 for heavy rotation.
5. **Write the files.** Write `public/data/<date>.json`, add the date to `public/data/index.json` (newest first, keep the last 14 days), and set `updated` to the current UTC time.
6. **Check and push.** Run `npm run check -- <date>` and `npm test`, and fix anything marked BAD. The check prices picks with the track-record calibration, so the best bets it prints are the ones the page shows. Then commit ("Data: <date> <morning|lineups|evening> update") and push to `main`.
7. **Record lessons.** When a graded result or a data problem leads to a change in the engine or in this runbook, add an entry at the top of `public/data/lessons.json`: `{date, area, kind: "model" | "data", saw, change}`. `saw` states what happened with real numbers from `results.json` or the source, and `change` states what is done differently now. The site shows these under "What the model learned". Scheduled data runs don't change the engine; they add a `data` lesson only when they change how data is collected.
