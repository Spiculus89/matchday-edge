# Data run runbook

This is what each scheduled run does. Each match follows the schema of the existing files in `public/data/` (use the newest one as the template).

0. **Grade yesterday (morning run only).** For each match in the previous day's file, add `result: {home, away}` and append every graded pick the site showed to `public/data/results.json` → `legs`: `{date, match, group, pick, p, odds, won}`. Include the best bet, every slip row whose verdict was Bet or Lean, the builder and any priced prop, using the chance the page showed. `group` must be one of Result, Handicap, Goals, BTTS, Scorer, Corners, Most corners, Cards, Bet builder or Player prop. Skip legs you can't settle from a reliable source. Never add games the user asked to keep off the site.
   - "The chance the page showed" means the engine run with the track-record calibration loaded (`setCalibration(trackStats(legs))` from `results.json`, as `index.html` and `scripts/check.mjs` do). Grade from `results.json` as it stood before today's legs were added. If `engine.js` changed after the games (an evening session), grade with the version that was live on match day (`git show <commit before the change>:public/engine.js`), since that is what the page showed (18 Nov).
   - If yesterday already has `result` fields and legs in `results.json` (an evening session graded it), don't add them again. If the day file has a `gradingTodo` list, grade only those items (props, cards, corners, matches without a result), then delete `gradingTodo`.
   - Grade a player prop only from a source that lists all of that player's shots, shots on target, fouls or tackles (an ESPN shot map, a box-score stat line). A booking or a partial live feed can show a prop landed but not that it lost, so those props stay ungraded, as do props for players who didn't play (15 Nov).
   - ESPN's match player-stats table and its player game logs (the FC column is fouls committed) give full shot, shot-on-target and foul lines. ESPN prints names and numbers in separate blocks, so check that the player rows add up to the team totals. ESPN has no tackles, so tackle props stay ungraded unless a full per-player source is found. If a match's ESPN pages only load as an in-game snapshot, leave all of that match's props ungraded, wins and losses alike (16 Nov: Latvia v Armenia).
1. **Pick the matches.** Find today's fixtures (Europe/Warsaw date) and keep 8–12 matches (more is fine when there are big rounds; the user asked for more than 4). Start with every top-tier European game of the day, then the rest of the same round (all Nations League A–D games on a Nations League night), then the best of the rest: Champions League, Premier League, La Liga, Serie A, Bundesliga, Ligue 1, Europa League, Nations League A, major internationals, then Ekstraklasa and other top leagues, plus big clubs and national teams. Skip youth and women's games unless nothing else is on.
   - File each match by its kick-off in Warsaw time. A 23:00 UK kick-off is 00:00 in Warsaw and belongs to the next day's file (13 Nov: Argentina v Uruguay).
2. **Gather the data for each match:**
   - **Odds:** bet365 odds from kickoff.co.uk (`/…-predictions-stats-odds/<home>-vs-<away>/`): 1X2, O/U 0.5–5.5, BTTS, double chance, DNB, win to nil, first goal. Cross-check 1X2, O/U 2.5 and BTTS against a second site (footballpredictions.ai, oddschecker, sportinglife). Never copy one match's ladder into another.
     - KickOff shows bet365 prices as fractions. Decimal = fraction + 1, rounded to 2 dp (11/20 → 1.55, 10/3 → 4.33, 1/40 → 1.03, 15/8 → 2.88).
     - If KickOff can't be fetched, try it again from the main run before falling back (on 13 Nov two research passes were blocked, a third fetch worked). When the ladder comes from elsewhere, `odds.book` must name the bookmaker and the site, and say which lines are missing.
   - **Stats:** statz.ai h2h page for the referee and their per-game fouls, yellows and reds; predicted or confirmed XIs; season per-game corners, fouls, shots and shots on target; top scorers and shooters; bet365 player props. If statz.ai has no page for the match, take the referee's numbers from UEFA match reports and say so in `referee.note`.
   - **Form:** kickoff.co.uk 20-game form, giving goals for/against and xG for/against.
   - **Team news:** injuries, suspensions, returns and new coaches from SoccerNews, Sports Mole, WhoScored, Oddschecker and the clubs' or federations' own posts.
   - **Smaller nations:** when no predicted XI is published, set `lineups.status` to `"pending"` with empty `xi` arrays and list the key players (top scorers, regular starters) with `start` 0.75. The kick-off-minus-40 run fills in the confirmed XIs.
   - **Lineups:** confirmed lineups about 60 minutes before kick-off from WhoScored "confirmed lineups", statz.ai, or federation and club accounts. Confirm with two sources.
   - **Doing it in parallel:** one research agent per match works well. Give each the schema, these rules and an output file, then check every file yourself before merging (odds margins, 11-man XIs, prop players present in `players`).
     - The agents share one search budget (about 200 searches per run; on 14 Nov it ran out partway through). Ask each agent to keep to about 15 searches.
     - Pages can only be opened when their link came back from a search, so search for the KickOff and statz.ai pages (`kickoff.co.uk Portugal vs Denmark`) before fetching them. Typed URLs are refused.
     - Games kicking off before noon Warsaw go first, in their own quick pass. If there are still no prices or team sheets, leave them off (14 Nov: Japan v Brazil at 11:15).
3. **Player props:** when bet365 props are listed, also give the player per-90 rates when you can find them (`shots90`, `sot90`, `fouls90`, `tackles90` from FBref, WhoScored or Sofascore). Without them the model falls back to position averages, which is deliberately cautious.
   - `fouls90` must be fouls committed. Some sources show fouls won under the same heading; an attacking player above about 1.5 per 90 needs a second source (13 Nov: Wirtz at 2.15 was dropped).
   - `hit` ("4/5") only when the source shows the last five games. A bare percentage with no game count is left out.
   - `teamTotals` must cover the same games as the players' `shots` and `goals`. If the spans differ, leave `teamTotals` (or that side) out.
4. **Build the players list:**
   - Starters get `start` 1 once confirmed and bench players 0.
   - Before that, players in the predicted XI get 0.75–0.9, rotation risks 0.3–0.5, and injured or suspended players are left out.
   - Set `adjust.home` or `adjust.away` to 0.92 when a confirmed XI is missing 2+ of the usual top-3 attackers, and to 0.96 for heavy rotation.
5. **Write the files.** Write `public/data/<date>.json`, add the date to `public/data/index.json` (newest first, keep the last 14 days), and set `updated` to the current UTC time.
6. **Check and push.** Run `npm run check -- <date>` and `npm test`, and fix anything marked BAD. The check prices picks with the track-record calibration, so the best bets it prints are the ones the page shows. Then commit ("Data: <date> <morning|lineups|evening> update") and push to `main`.
7. **Record lessons.** When a graded result or a data problem leads to a change in the engine or in this runbook, add an entry at the top of `public/data/lessons.json`: `{date, area, kind: "model" | "data", saw, change}`. `saw` states what happened with real numbers from `results.json` or the source, and `change` states what is done differently now. The site shows these under "What the model learned". Scheduled data runs don't change the engine; they add a `data` lesson only when they change how data is collected.

## Odds feed (OddsPapi)

- A GitHub Action (`.github/workflows/odds.yml`, key in the `ODDSPAPI_KEY` repository secret) fetches odds at about 08:40, 18:15 and 00:10 Warsaw. It writes `public/data/odds/latest.json` and merges prices into upcoming games on the site; games that have started are never touched.
- Books: **Pinnacle** is the main price (sharpest, best for fitting the model). **AdmiralBet BA** is the local comparison (the user bets at Meridian, which OddsPapi doesn't carry), stored in `odds.local`.
- **Morning build:** read `latest.json` first and use it for every game it covers. Search the web only for games or lines it lacks, and mark guessed prices in `odds.assumed` as before.
- **Budget:** the free tier is ~200 requests a month and the script stops at 190 (`public/data/odds/usage.json`). Each run costs 1–2 requests, so don't trigger extra runs except for something important. To run it on demand, commit a new line to `.github/odds-request` starting with `fetch`.
- Tournament IDs live in `data/odds-config.json`. Add a league's ID there (look it up in `data/odds-cache/discover.json`) when the site starts covering it.

## Basketball and ice hockey

The menu at the top switches between `index.html` (football), `basketball.html` and `hockey.html`. Each sport has its own folder: `public/data/basketball/` and `public/data/hockey/`, each with `index.json`, `<date>.json` and `results.json`. Use the newest day file as the template; the engines are `engine-basketball.js` (`HoopsEngine`) and `engine-hockey.js` (`HockeyEngine`).

1. **Grade yesterday** exactly as for football: add `result: {home, away, ot}` (`ot` = "OT" or "SO" when it went past regulation) and append graded picks to that sport's `results.json`. Groups: basketball `Moneyline`, `Spread`, `Total`, `Team total`, `1st half`, `Player prop`, `Bet builder`; hockey `Moneyline`, `60-min result`, `Puck line`, `Total`, `BTTS`, `Team total`, `1st period`, `Player prop`, `Bet builder`. NHL moneyline, puck line and totals include OT and the shootout (a shootout adds one goal to the winner); 60-minute markets settle after regulation. Pushes on whole-number lines are `void: true`.
2. **Pick the games** (Warsaw date; a 01:30 tip-off belongs to that day's file):
   - Basketball, 8–14 games: about half NBA (best records, stars, national TV) and half European. Europe: every EuroLeague game (Tue–Fri), then the best EuroCup, Basketball Champions League and ABA games (always include KK Bosna Royal and Igokea games, which the user follows), and at weekends the top games in ACB, Lega A, Greek, Turkish and French leagues. European games start in the evening Warsaw time, so they go in **that day's** file; NBA games after midnight go in the next day's file.
   - European odds come from `public/data/odds/latest.json`: each morning's feed run fetches the European watch list (`data/odds-config.json`, midweek = cups, weekend = domestic leagues). `league` must name the competition, e.g. "EuroLeague, Round 12", "EuroCup, Group D", "Basketball Champions League, Group B", "ABA League", "Liga ACB", so the odds feed can match it (aliases in `data/odds-config.json`).
   - European team news: the EuroLeague publishes an official injury report each round (euroleaguebasketball.net, also on Eurohoops); EuroCup pregame quotes and injury reports on euroleaguebasketball.net/eurocup; BCL on championsleague.basketball. Form `{pf, pa, games}` from the competition standings (eurobasket.com standings pages list PPG and OPPG).
   - Hockey, 4–8 games: the NHL's best games first, then KHL / SHL / Liiga / NL top games on days with few NHL games.
3. **Odds** (decimal; convert American: +150 → 2.50, −150 → 1.667):
   - Basketball: `ml [home, away]`, `spread {line (home view, e.g. -5.5), h, a}`, `total {line, o, u}`; optional `teamTotal {home:{line,o,u}, away:…}`, `h1 {spread, total}`. Sources: DraftKings Network public-betting pages, FanDuel Research, Covers, ESPN scoreboard, NBC/Rotoworld previews. If only a line is published, price it at −110, say so in `odds.book`, and list those markets in `odds.assumed` (e.g. `["spread", "total"]`). The engine never makes an assumed price a Bet or the best bet (18 Nov: both losing best bets came from assumed prices, and the real Lakers line had moved). Look for the real price first (Covers, FanDuel Research, ESPN BET); an assumed price is the last resort.
   - Hockey: `ml [home, away]` (incl. OT), optional `reg [home, draw, away]` (60 min), `puck {line (home view), h, a}`, `total {line, o, u}`, optional `btts`, `teamTotal`, `p1total`. Sources: BetMGM "prediction-odds-picks" pages, DraftKings Network, Yahoo/Covers previews. BetMGM tables list the over on the first row and the under on the second.
4. **Form:** basketball `form.home/away {pf, pa, games}` (season points per game for and against, e.g. champsorchumps.us or ESPN standings); hockey `form {gf, ga, sog, games}` (goals for/against and shots per game, ESPN team pages or statmuse).
5. **Players:** basketball `{name, pos, pts, reb, ast, threes, min, status, start}`; hockey `{name, pos (C/LW/RW/D/G), gp, g, a, sog (season totals) or perGame: true}`. `status` from the official NBA injury report (ak-static.cms.nba.com PDFs) or the NHL injury lists; set `start` 0–1 for questionable players. Props: `{player, market: "Over 25.5 points" | "Over 3.5 shots on goal" | "Anytime goalscorer" | "Over 27.5 saves", odds, hit}`.
6. **Injury news after the odds:** basketball `adjust.home/away` in points (negative, e.g. −3 for a 25-point scorer ruled out after the line was set); hockey multiplicative like football (0.92 when a top-line forward or the starting goalie is a late scratch).
7. **Before tip-off / puck drop:** confirmed NBA starters about 30 minutes before tip-off, NHL starting goalies after the morning skate. Put them in `lineups.home/away` (names) with `status: "confirmed"`.
8. **Check:** `npm run check-sport -- basketball <date>` and `npm run check-sport -- hockey <date>`, plus `npm test`.
